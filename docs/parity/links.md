Testing on Linux without touching the default handler of the session: put the `.desktop` file in an isolated `XDG_DATA_HOME/applications`, write `x-scheme-handler/discord=discord-phoenix.desktop` in an isolated `XDG_CONFIG_HOME/mimeapps.list`, and run `xdg-open` with `XDG_CURRENT_DESKTOP` unset so it uses the generic path. The official client keeps the user's handler.

Real test (27/11, 17:58): int-bin `1b9f9211` under Xvfb with its own `XDG_CONFIG_HOME` / `XDG_CACHE_HOME` (keyring token, `PHX_AGENT=1`), started on #général; `xdg-open discord://-/channels/1369382919948210248/1574797385463496724` with an isolated `XDG_CONFIG_HOME/mimeapps.list` and `XDG_DATA_HOME/applications`. The second process started, handed the URL over and exited; the running window logged `open url target=Some("channel")` 77 ms later and showed #phoenix. The session default handler stayed unchanged. Found during the test and fixed: socket paths over the 108-byte Unix limit (long profile directories) now fall back to a hashed name in the temp dir, and the main binary no longer sends read acks when `PHX_AGENT` is set.
